# LOB Browser 实施计划

## 1. 要掌握的系统是什么

浏览器 Agent 是页面感知、动作空间、模型决策、执行反馈、状态管理和安全治理的组合，而不是一组自动化脚本。

```text
Task → Browser Session → Observe → Decide → Validate → Act
                           ↑                         │
                           └──── Page Change ←──────┘
                                      │
                         Complete / Retry / Approve
```

每个阶段都必须回答：模型看到了什么、动作如何定位目标、执行后如何证明页面发生了预期变化、失败能否分类恢复，以及哪些操作必须交给用户确认。

## 2. 核心领域对象

```text
BrowserSession
  ├─ BrowserContext
  ├─ Tab
  │   └─ PageState
  │       ├─ URL / Title
  │       ├─ InteractiveElement
  │       ├─ TextSnapshot
  │       └─ ScreenshotRef
  └─ TaskRun
      ├─ Step
      │   ├─ Observation
      │   ├─ ModelDecision
      │   ├─ Action
      │   └─ ActionResult
      ├─ Approval
      └─ Event / Artifact
```

## 3. 分阶段实施

### 阶段 0：项目定位、领域模型与实施计划

目标：明确与 browser-use、Playwright、LOB 系列项目的边界，固定研究版本和验收任务。

任务：

1. 固定 browser-use 版本、许可证和源码提交。
2. 定义 BrowserSession、Tab、PageState、Action、Step 和 TaskRun。
3. 建立动作风险等级与人工审批原则。
4. 准备登录表单、动态列表、弹窗和多标签页等本地测试页面。
5. 固定首条端到端任务及预期事件序列。

验收：能解释完整 Agent 调用链、状态边界和项目不实现的能力。

### 阶段 1：浏览器会话与确定性动作闭环

目标：不接模型，先实现稳定可测的浏览器控制层。

任务：

1. 启动、连接、关闭 Chromium，隔离 BrowserContext。
2. 实现 Navigate、Back、Reload、Click、Type、Select、Scroll、Wait。
3. 实现标签页创建、选择和关闭。
4. 统一 Action、ActionResult 与错误分类。
5. 保存动作前后 URL、标题、耗时和页面摘要。
6. 支持超时、取消和资源清理。

验收：确定性脚本可完成本地表单任务；错误元素、超时和页面关闭都有明确结果。

### 阶段 2：页面感知与可交互元素抽取

目标：把复杂网页压缩为模型可消费、可定位的观察结果。

任务：

1. 提取可见文本、表单控件、按钮、链接及 ARIA 信息。
2. 为可交互元素分配单次观察内稳定的索引。
3. 过滤隐藏、禁用、遮挡和无意义节点。
4. 处理 iframe、Shadow DOM 和可滚动区域。
5. 生成 DOM 摘要、截图引用和 Token 预算统计。
6. 页面变化后识别失效元素，禁止复用陈旧索引。

验收：固定页面的观察结果稳定；模型上下文能准确描述目标控件且不包含敏感字段值。

### 阶段 3：模型驱动的 Browser Agent Loop

目标：让模型基于页面观察选择结构化动作并完成任务。

任务：

1. 定义统一模型请求、动作 Schema 和完成结果。
2. 实现 Observe → Decide → Validate → Act 循环。
3. 校验动作类型、参数、元素索引和当前页面版本。
4. 支持完成、失败、最大步数和 Token 预算终止。
5. 保存模型决策、动作理由、执行结果和页面变化。
6. 对无效动作提供可恢复反馈，避免盲目重复。

验收：模型能完成至少三类本地网页任务；每一步可回放并说明为何终止。

### 阶段 4：动态页面、标签页与复杂交互

目标：覆盖真实网页任务中的异步和多页面场景。

任务：

1. 等待导航、网络空闲、元素出现和业务条件。
2. 处理 SPA 局部更新、懒加载和无限滚动。
3. 处理新标签页、弹窗、确认框和 iframe。
4. 支持文件下载，并记录产物来源和校验信息。
5. 在明确授权下支持文件上传。
6. 支持登录态复用，但不读取或回传浏览器凭据。

验收：可完成包含异步加载、新标签页和下载的固定任务；页面变化不会导致动作错投。

### 阶段 5：可靠执行、恢复与人工审批

目标：让失败可分类、可恢复，让高风险动作可控。

任务：

1. 区分定位失败、页面变化、超时、网络、权限和模型错误。
2. 实现有限重试、退避、重新观察和替代定位。
3. 保存 Checkpoint，进程重启后识别未完成任务。
4. 对可安全重放的步骤提供恢复；副作用步骤使用幂等保护。
5. 对发布、删除、支付、发送和权限变更建立审批策略。
6. 支持暂停、批准、拒绝、取消和审计记录。

验收：元素失效后可重新观察恢复；拒绝审批后不执行目标动作；恢复不重复副作用。

### 阶段 6：记忆、任务规划与多 Agent

目标：支持更长任务并控制上下文增长。

任务：

1. 压缩历史观察与步骤，仅保留任务相关状态。
2. 维护任务目标、已完成事项、失败尝试和待办计划。
3. 支持 Planner 与 Executor 分工。
4. 支持独立浏览器上下文中的受控子任务。
5. 限制子 Agent 数量、总步数、Token 和时间预算。
6. 合并子任务结果并处理冲突。

验收：长任务上下文保持有界；子任务隔离且总预算可控。

### 阶段 7：评测、可观测与生产化

目标：量化任务成功率、成本、速度和安全性。

任务：

1. 建立固定任务集、页面快照和成功判定器。
2. 记录任务成功率、步骤数、耗时、Token 和恢复次数。
3. 提供 Task、Step、模型请求和浏览器动作统一 Trace。
4. 支持失败回放、截图时间线和敏感信息脱敏。
5. 引入并发控制、Worker、资源配额和优雅停机。
6. 验证浏览器崩溃、Worker 中断和服务重启行为。

验收：每次版本变更可运行回归任务集；失败可定位到具体观察、决策或动作。

### 阶段 8：browser-use 源码映射与差异清单

目标：能定位 browser-use 的关键入口并解释实现取舍。

任务：

1. 追踪一次完整任务的 API、Agent、Browser 和 Event 调用链。
2. 映射页面状态抽取、DOM 序列化和元素定位模块。
3. 映射动作注册、执行、结果反馈与异常处理模块。
4. 映射消息构建、历史压缩、完成判断和模型调用模块。
5. 映射会话、Watchdog、截图、下载和审批相关入口。
6. 形成“browser-use 对象 → LOB Browser 对象 → 差异与原因”清单。

验收：至少完成页面观察、动作执行、Agent Loop、失败恢复四条源码调用链映射。

## 4. 推荐模块边界

```text
src/lob_browser/
  browser/       浏览器、Context、Tab 生命周期
  observation/   DOM、元素、文本和截图观察
  actions/       动作协议、校验、执行和结果
  agent/         模型决策、循环、预算和完成判断
  runtime/       Task、Step、事件、取消和恢复
  approval/      风险策略、审批和审计
  providers/     模型供应商适配
  evaluation/    任务集、判定器和指标
```

## 5. 首批验收任务

1. 表单任务：填写多个字段、选择选项并提交，验证成功提示。
2. 动态列表：搜索、等待异步结果、打开详情并提取目标字段。
3. 多标签任务：点击链接打开新标签页，读取信息后返回原页面。
4. 失败恢复：目标元素被替换后重新观察并继续。
5. 审批任务：执行模拟发布前暂停，批准后继续，拒绝后终止。

## 6. 统一完成标准

- 每个阶段保留固定输入、预期结果和失败样例。
- 关键状态变化必须有事件，不能只依赖日志文本。
- 页面和模型的不确定性必须被限制在可观察、可终止的边界内。
- 不为通过演示而绕过网站权限、验证码或安全确认。
- 每项实现都记录 browser-use 源码映射与刻意简化点。
